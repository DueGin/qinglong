# 脚本文件管理页锁功能实现说明

## 功能概述

在脚本文件管理页面实现了细粒度的文件锁控制，确保多端登录时的文件编辑互斥。

## 实现的功能点

### 1. 选择文件时检查锁状态
- ✅ 用户点击某个文件后，自动检查该文件的锁状态
- ✅ 根据锁状态设置"编辑"和"调试"按钮的可用性
- ✅ 如果文件被他人锁定，显示警告提示

### 2. 编辑按钮点击逻辑
- ✅ 点击"编辑"按钮时，尝试获取文件锁
- ✅ 获取成功：进入编辑模式，可以编辑和保存
- ✅ 获取失败：显示错误提示，说明谁正在编辑

### 3. 调试按钮点击逻辑
- ✅ 点击"调试"按钮时，尝试获取文件锁
- ✅ 获取成功：打开调试窗口，可以运行和调试
- ✅ 获取失败：显示错误提示，按钮禁用

### 4. 保存文件后的锁处理

#### 非调试模式（主页面编辑）
- ✅ 保存成功后，**自动释放锁**
- ✅ 退出编辑状态，回到只读模式
- ✅ 其他用户可以立即编辑该文件

#### 调试模式（调试窗口）
- ✅ 保存成功后，**保持锁定状态**
- ✅ 用户仍然在调试窗口中，可以继续编辑和运行
- ✅ 其他用户仍然无法编辑该文件

### 5. 退出编辑/调试的锁处理
- ✅ 点击"退出编辑"按钮：释放锁
- ✅ 关闭调试窗口：**不释放锁**（文件仍被选中，可能继续操作）
- ✅ 切换到其他文件：自动释放当前文件的锁

### 6. 锁状态的实时同步
- ✅ 通过 WebSocket 实时接收锁状态更新
- ✅ 当其他用户获取/释放锁时，立即更新按钮状态
- ✅ 显示当前锁定者的用户名

### 7. 用户界面提示
- ✅ 文件被他人锁定时，编辑器上方显示黄色警告条
- ✅ 提示信息包含锁定者的用户名
- ✅ 编辑和调试按钮被禁用

## 详细工作流程

### 场景 1：正常编辑流程
```
1. 用户选择文件 A
   → 检查锁状态（未被锁定）
   → "编辑"和"调试"按钮可用

2. 用户点击"编辑"按钮
   → 获取文件 A 的锁
   → 进入编辑模式

3. 用户修改文件并保存
   → 保存成功
   → 自动释放锁
   → 退出编辑模式

4. 其他用户可以编辑文件 A
```

### 场景 2：调试流程
```
1. 用户选择文件 B
   → 检查锁状态（未被锁定）
   → "编辑"和"调试"按钮可用

2. 用户点击"调试"按钮
   → 获取文件 B 的锁
   → 打开调试窗口

3. 用户在调试窗口修改代码并保存
   → 保存成功
   → **保持锁定**（不释放锁）
   → 仍然在调试窗口中

4. 用户关闭调试窗口
   → **保持锁定**（文件仍被选中）
   → 用户可以继续点击"编辑"或"调试"

5. 用户切换到其他文件
   → 自动释放文件 B 的锁
```

### 场景 3：多端冲突
```
用户 A（标签页1）:
1. 选择文件 C
2. 点击"编辑"
3. 获取锁成功，进入编辑模式

用户 A（标签页2）:
1. 选择文件 C
2. 显示警告："用户 A 正在编辑此文件"
3. "编辑"和"调试"按钮被禁用

用户 A（标签页1）:
4. 保存并退出编辑
5. 释放锁

用户 A（标签页2）:
6. 实时收到通知，按钮恢复可用
7. 现在可以编辑文件 C
```

## 代码修改清单

### 主页面 (src/pages/script/index.tsx)

#### 新增状态
```typescript
const [lockInfo, setLockInfo] = useState<LockInfo | null>(null);
const [isLocked, setIsLocked] = useState(false);
const wsRef = useRef<WebSocketManager | null>(null);
```

#### 新增函数
- `getFilePath(node)` - 获取文件完整路径
- `checkFileLock(node)` - 检查文件锁状态
- `acquireFileLock(node)` - 获取文件锁
- `releaseFileLock(node)` - 释放文件锁

#### 修改的函数
- `onSelect()` - 添加锁状态检查
- `editFile()` - 编辑前获取锁
- `cancelEdit()` - 退出时释放锁
- `saveFile()` - 保存后释放锁
- `onTreeSelect()` - 切换文件时释放锁

#### 新增 useEffect
- WebSocket 事件监听
  - `lockAcquired` - 锁获取成功
  - `lockFailed` - 锁获取失败
  - `lockStatus` - 锁状态更新

#### UI 修改
- "编辑"按钮：根据锁状态禁用
- "调试"按钮：根据锁状态禁用，点击时获取锁
- 编辑器上方：显示锁定警告

### 调试窗口 (src/pages/script/editModal.tsx)

#### 移除
- 移除 `useFileLock` Hook（锁已在主页面管理）
- 移除只读模式的警告提示
- 移除按钮的禁用逻辑

#### 原因
调试窗口不需要单独管理锁，因为：
- 锁已经在打开调试窗口前获取
- 保存文件时不释放锁
- 关闭调试窗口时不释放锁

## 关键设计决策

### 为什么调试模式保存不释放锁？
因为调试模式是一个独立的全屏窗口，用户：
- 仍然在编辑和调试状态
- 可能会多次保存和运行
- 关闭窗口后仍然可以继续操作

### 为什么关闭调试窗口不释放锁？
因为：
- 文件仍然被选中（在主页面）
- 用户可能想快速再次打开调试
- 只有切换到其他文件时才释放锁

### 为什么编辑模式保存要释放锁？
因为：
- 保存后自动退出编辑模式
- 回到只读状态
- 用户需要重新点击"编辑"才能再次编辑
- 符合传统编辑器的使用习惯

## 用户操作指南

### 正常编辑文件
1. 在左侧树中选择要编辑的文件
2. 点击"编辑"按钮
3. 编辑完成后点击"保存"
4. 自动退出编辑模式，锁被释放

### 调试文件
1. 在左侧树中选择要调试的文件
2. 点击"调试"按钮
3. 在调试窗口中编辑和运行
4. 保存后锁仍然保持
5. 关闭调试窗口后锁仍然保持
6. 切换到其他文件才会释放锁

### 文件被锁定时
- 会看到黄色警告提示
- "编辑"和"调试"按钮被禁用
- 可以查看文件内容
- 等待锁定者完成操作
